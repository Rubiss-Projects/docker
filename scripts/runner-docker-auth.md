# Docker credentials for the Ubuntu deployment runner

The main-host Actions runner runs as `rubiss` in Ubuntu systemd. After WSL restarts from an SSH or service session, Docker Desktop's Windows credential helper can fail with `A specified logon session does not exist`. Docker's engine and existing containers can be healthy while every Compose pull fails.

The runner uses a separate Docker CLI configuration at `/home/rubiss/actions-runner-docker-ops/.docker-ci/config.json`, selected by the systemd drop-in `runner-docker.service.conf.example`. The example configuration contains no credentials and pulls public images anonymously. It leaves `/home/rubiss/.docker/config.json`, Windows Credential Manager, and Docker Desktop's interactive login unchanged. Anonymous registry rate limits still apply; do not retry a rate-limited pull continuously. Private registries or higher authenticated allowances require a deliberate Linux-compatible credential setup for this runner.

To provision a new runner, create the `.docker-ci` directory owned by `rubiss:rubiss` with mode `0700`, and install `runner-docker-config.example.json` there as `config.json` with mode `0600`. Install `runner-docker.service.conf.example` as `/etc/systemd/system/actions.runner.Rubiss-Projects-docker.Ben-Server-wsl-docker-ops.service.d/docker-ci.conf`. Adjust the service and home paths for a different host. Inspect any existing configuration before installing; do not overwrite credentials or a runner override.

Wait for any active job to finish, run `systemctl daemon-reload`, and restart that runner service. From its service account, verify Docker engine access, `docker compose version`, and a public image manifest with the dedicated `DOCKER_CONFIG`. Then rerun failed deployment jobs through GitHub Actions and verify the deployed image, container health, and original data mounts. Do not print credential-helper output or raw Docker configuration to workflow logs.

During Docker Desktop or WSL maintenance, pause the runner until Docker integration and data mounts are ready. If Ubuntu will restart during the outage, record the runner's enabled state and temporarily disable it as well as stopping it. Resume it only after verification, then reconcile queued or interrupted deployment runs. Keep the Docker restart watchdog paused through this recovery so it cannot race the deployments; restore its previous state afterward.

On September 5, 2026, this configuration restored the public-image pull path after the Ubuntu migration to E:. Recyclarr and Bitwarden deployment reruns passed with the runner using this configuration. See Docker's [credential store documentation](https://docs.docker.com/reference/cli/docker/login/#credential-stores) for the distinction between Desktop's operating-system keychain and a Linux service's credentials.
